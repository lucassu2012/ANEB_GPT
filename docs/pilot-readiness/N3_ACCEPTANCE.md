## 已知问题与修复范围

- 截图有 READY，但混在日志中；地址未分类，虚拟网卡也被当作普通 Node URL。改为醒目中文就绪、一个优先尝试地址、其他局域网及高级备选。推荐只是本机提示，手机可达性须实际 Compatible。
- 试用者不清楚测试目的，Prototype 页面缺中文。复用既有页面解释合成流式测试，补中文操作/结果/错误与关键指标标签，不新增状态机。
- Quick3、Acceptance9 运行成功且原节点各自 evidence verifier 通过；用户确认 Saved 可重新打开。不能由此断言试用者独立连接或理解通过。

不改 workload、运行时钟、编排、RPI-0.1、证据 schema、claim 或 G2–G5。保留原发布 ZIP、签名/散列和历史证据。手机五文件备份仍是 unverified；原节点七文件才是正式报告验证路径。

## 一次候选的八项检查

全部现场项目前 **NOT_RUN on N3**。定点/完整代码测试与现场结果分栏记录，不继承 0.1 或 P01 原包设备 PASS。每项分别登记“独立完成 / 经协助完成 / 未完成”，不能将协助后的成功记为独立通过。

| 检查 | 通过要求 |
|---|---|
| 1. Windows 就绪 | 普通用户双击原 BAT，在中文/空格解压路径也能看到醒目中文 READY、明确结果目录与 Q/Enter 停止说明；本机就绪不等于手机连通 |
| 2. 选择地址 | 有 Wi-Fi 时优先显示一条 Wi-Fi 地址；有线为备选；虚拟/未知独立分组。无物理推荐时如实提示，不伪造已验证可达 |
| 3. 理解目的 | 首屏/确认页用中文说明手机到所选节点的应用层合成对比、三条件、Quick 每组一次/Acceptance 每组三次；用户能复述不是运营商评级或真实 AI 跑分 |
| 4. 连接 | 使用显示地址检查节点，实际出现“兼容 / Compatible”；错误仍保留 P006/P007 等诊断码与自救步骤，不自动改防火墙/网络配置 |
| 5. Quick / Acceptance | 使用新 campaign ID，分别 3/9 个 run；状态、取消/中断和本地保留均真实，失败不充当零值或成功 |
| 6. 指标结果 | TTFT、Completion、Stall、Success Rate、RPI 有中文解释；保留数值/单位/null 与诊断；RPI 限同一个 campaign，不是全网评级 |
| 7. Saved / 导出 | 从已保存列表打开同一结果、不自动重跑；手机导出/分享明确未验证备份；正式报告到原节点七文件目录验证，verified 不等于运行成功 |
| 8. 安全结束 | Windows Q/Enter 退出已知节点；按 AGENTS 停止本次所启应用/服务/转发/临时设置并回 Launcher，保留结果；未知会话不强停 |

## 交付门

1. 唯一整合 PR；Windows guidance + 原 BAT 回归；完整 `scripts/quality_gate.ps1`；CI 全绿。
2. 新候选必须另给精确源码、APK/ZIP SHA-256、批准 signer 验证；不能把 debug assemble 当可发布签名包。
3. 候选到达后才按 live AGENTS 做 P40 前置与上述一次验收。用户理解一项保留真实反馈，不由自动化代答。
4. 缺候选、手机非 clean、出现数据/身份/证据冲突即停在该门。现有发布版本不覆盖，云端保持原状。
