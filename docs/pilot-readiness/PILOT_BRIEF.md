# 首个试点交付卡

状态：**DRAFT / 尚未对外报价、联系或执行**。基线：[已发布 Prototype 0.1](https://github.com/lucassu2012/ANEB_GPT/releases/tag/prototype-0.1)。

## 适用问题

［INFERRED｜MED］面向研究或网络体验技术团队，验证“第二位操作者能否使用固定包完成合成条件比较、正确解释结果并独立复核证据”。如果需求是第三方 App 排名、运营商 SLA 或无线网络诊断，当前产品不适配，不通过改措辞成交。

## 三项服务交付建议

［FRAME｜LOW］以下是待约定的服务单元，不宣称已向客户交付：

1. 原 ZIP、两份包外回执、版本索引和操作说明；操作员承担包/签名检查，不要求普通参与者懂哈希。
2. 一次 Quick 3-run 与一次 Acceptance 9-run 的节点七文件目录、原包验证结果和离线报告。真实失败/取消原样交付，不以高 RPI 作为服务验收条件。
3. 一页结果解释、异常及未完成项、交接/支持记录；明确手机五文件 ZIP 只是未验证备份。

［FRAME｜LOW］计价单位建议为“一个固定版本 × 一个约定环境/站点 × 一次交付与解读”。新增设备、站点、再次现场实施或定制报告另行确认范围。本稿不定价格、不收款、不承诺响应时限；没有订阅/支付 UI。服务条款、软件许可、保留期和支持窗口须在实际报价前确认。

## 五步开始

1. 操作员核对发布页的原 ZIP 与两份包外回执。完整解压到新可写目录，不覆盖旧 `results`，不混换单文件。
2. 双击 `START_ANEB.bat`，等待 READY。电脑和手机使用双方许可且可互访的局域网；READY 不等于手机已连通。需要入站权限时请场地管理员处理，不关闭防火墙、不把 Public 强改为可信。
3. 保存手机重要结果，再安装包内 APK。已验证 Windows x64＋Huawei P40 Pro；其他设备标 UNKNOWN。签名冲突时停止，不绕过安装验证或擅自卸载。
4. Prototype Mode 填节点地址，Test connection 显示 Compatible 后，依次开始一次 Quick、一次 Acceptance。分别保留新 campaign ID；不重复运行凑通过。
5. 每个结果点击 Export ZIP，等待明确保存确认；失败如实记录，不能用节点七文件替代手机备份。打开节点 `results/<campaign_id>/report.html`；操作员按[发布说明](../prototype-0.1/RELEASE_HANDOFF.md)执行原包离线验证，保留退出码及输出，备份整个七文件目录。最后在原启动器输入 Q 并等待实际退出，按[操作表](OPERATOR_CHECKLIST.md)清理本轮资源。

## 如何解释、失败时怎么办

［KNOWN｜HIGH］先看状态和成功数，再看 TTFT、Completion、Stall 与 RPI/null reason。验证退出码 0＋`G0_VERIFY_OK` 表示证据合同通过，不代表测量成功。缺失不是零。合成条件不代表第三方 App、IP 丢包、无线/RAN、MOS、运营商评级或 SLA。

- 连不上或不兼容：记录实际错误，核对原节点与整包身份，不更改合同或关闭保护。
- 中断/取消：保留部分证据和空 RPI；新的测量使用新任务，不覆盖原失败。
- 发布失败：按完整 ID 与原节点从 Saved campaigns 重开；操作员确认恢复原节点后才显式 Retry evidence publication。它只重新发布已有证据，不重测、不改成成功；冲突不得覆盖。
- 包校验/签名错误、证据不一致、未知占用或无法确认安全退出：停止受影响步骤，保留记录，不盲试或强停未知会话。
