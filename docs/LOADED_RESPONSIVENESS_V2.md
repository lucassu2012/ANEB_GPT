# 负载响应性 v2：有界阶段与请求来源

状态：PO于2026-10-24选择B批准离线实现与质量门；不是实机数值验收通过。
v1和既有partial原件保持原义。v2方法ID为`loaded-responsiveness-v2`，不重新解释旧报告。

## 保持不变

复用Basic引擎、AnebClient、Room/report_body、历史与Exporter；不增综合引擎、评分或数据库迁移。
basic_network/0.1.0的20次idle、下载10秒/4并发/32MiB、上传10秒/2并发/8MiB及尾部echo不改。
echo间隔250ms、单颗2秒；四戳/阶段边界/字节重叠/路径绑定、P50/P95线性插值、允许负增量不改。
旧Basic/Token/Prototype调用不接入v2记录器，不增加回调等待；旧v1解码/派生及原始JSON不变。

## 新的事实接口

每个负载阶段有`executionV2`：计划截止、停止发起时间、明确停止原因、快照时刻及逐请求记录。
每条请求绑定requestId、workerId、方向、请求大小、开始时刻；记录真实响应头/HTTP码、body开始/完成、
累计观测字节、取消请求来源及实际call.cancel调用、回调结束时刻、首个失败事实。
没有观察到的事件保持null；未知原因不能猜成用户取消或正常截止；只记异常类型，不记录业务内容/凭据。
HTTP回调结束须在消费和Response关闭之后；协程cancelAndJoin不能替代这个事实。

## 阶段资格

只有控制器按计划到时主动停止、时序一致且所有请求回调已确认结束的阶段，才可能用于v2统计。
有完整请求成功不是必要条件；正常到时取消并不宣称那个请求完整成功。
显式调用自有call.cancel之后，OkHttp报告的取消后IO作为独立诊断保留，不伪造成HTTP成功。
已观察到的真实失败先于正常清理时不得被后来的deadline取消覆盖；非2xx、未知/外部取消、路径失效及
未确认排空不得用“有字节”放行。无法核定来源则null。
这只界定客户端已观察到的阶段，不证明不可见的网络物理事件或未发生网络故障。

下载重叠须关联到真实2xx响应的body字节；上传只主张客户端写入重叠，未收到最终HTTP时保持HTTP=null，
不能由写完字节推导远端接收或2xx。已观察到的非2xx/非取消失败仍拒绝。
v2每条正字节回调绑定requestId，按来源请求的body/HTTP时序及累计值对账；不能用阶段内另一请求的2xx认证未知来源字节。
原有逐echo成功、四戳、阶段内与字节重叠资格继续独立检查；阶段外排空记录留raw，不入测量。
回调关闭最多等待2秒，超限明确中止/保留部分原件，不继续下一阶段，不延长观测窗口，不自动重试。

## 本轮离线验收顺序

1. 正常截止且下载已见2xx/body字节、无EOF：允许已证实重叠的echo；先RED后最小实现。
2. 同前缀字节但提前IO失败、用户/未知取消：拒绝，失败来源不能被清理覆盖。
3. worker结束但HTTP回调未结束：冻结前确认排空；未确认则null。
4. 上传写入但无最终HTTP：仅按客户端写入语义；HTTP错误不能被写入量洗白。
5. v1编码/解码/旧partial与所有旧模式回归；实际producer hook和取消排空用本地受控HTTP fixture测试。
6. 固定候选后一次完整quality_gate；保留精确APK SHA和原始结果。通过不授权第二个P40样本。

本轮不接触P40/E-01/Aliyun、生产signer/发布或上传关闭，不恢复千问，不重算旧run的替代KPI。
