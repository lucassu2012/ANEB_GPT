## 计量缺陷与修正

首轮 run `019f6e8c-24ba-7f04-9409-c4c054926535` 的上行显示 2.26Mbps，超过 1Mbps 合同。检查原始实现后确认：客户端累计的是写入 OkHttp/socket 缓冲区的字节，而不是服务端已接收字节；该 run 的上行值被否决，不能作为验收证据。

修正后弱网 Profile 使用 128KiB 双连接上传块，客户端解析 `/upload` 服务端回执，只累计服务端确认的完整字节；回执缺失、解析失败或字节不匹配均记失败，不计 0 或本地写入量。

## 结论边界

- 下载下降 84.2%、上传下降 92.9%，网络综合分下降 19.2 分，证明 App 的容量指标与评分能感知该合成刺激。
- 空闲 RTT P95 增加 118.24ms，接近合同声明的 +120ms，证明请求级附加时延生效。
- loaded RTT 没有随合成弱网单调增加；正常路径满载时的实际排队更严重。该现象必须保留，不能用“弱网理应更慢”的预期覆盖实测。
- UDP 200/200 只证明当时未整形 UDP 探针可达，不能解释为模拟丢包率为 0。
- 本结果不能外推为真实 RSRP/SINR 弱覆盖、蜂窝小区拥塞、运营商 SLA 或第三方 AI 服务质量。
